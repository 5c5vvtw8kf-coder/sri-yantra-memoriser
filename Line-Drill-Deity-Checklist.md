**Major correction — C4/C5/C6/C7 chant-order-to-position mapping bug (2026-07-29):** Everything below for circuits 4–7 has been recomputed and is a significant correction to all earlier passes. The app does **not** place chant sequence N at the Nth triangle going around the ring for these four circuits — each has its own `C{n}_DEITY_ORDER` remapping array (in `C4View.jsx`/`C5View.jsx`/`C6View.jsx`/`C7View.jsx`, also duplicated in `SpotCheckView.jsx` and `deityPositions.js`) that scrambles chant order onto physical position. Example, straight from `C4View.jsx`'s own comment: *"Starts at bottom centre (deitySeq 8, chant seq 1), runs clockwise up the right side, across the top, down the left side."* So chant-seq-1 (sarvasaṅkṣōbhiṇī) is physically at the **bottom** of the C4 ring, not the top. Every C4–C7 position used earlier in this design exercise (this session and prior) was computed by reading the triangle in ring order directly, skipping this remapping — so most "committed" C4–C7 line picks from earlier passes were checking the *wrong physical triangle* for a given chant name. This is also the real explanation for the "top vs. bottom C4 mix-up" note below: L12 clipping sarvasaṅkṣōbhiṇī was Chris's original, correct read; my rejection of it was the bug.

All C4–C7 rows below are now computed via each circuit's real `DEITY_ORDER` array, verified against a script that reads L1–L13's actual drawn coordinates from the HTML (not hand-typed anchor points), and cross-checked with a genuine polygon-crossing test (not just centroid distance) for every triangle. C1/C2/C3/C8/C9 were unaffected by this bug (they don't use a `DEITY_ORDER` remap) but were regenerated through the same script for consistency and turned up a few extra exact hits the old manual arithmetic missed (māhēśvarī on L5, brāhmī also on L9).
